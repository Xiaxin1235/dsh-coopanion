## 原因与修订

差异来自两层。旧绑定分别填满部件矩形，导致头身、发长、裙身、四肢、眼位和腰结比例漂移；旧拆件又对母版进行了重绘，短密卷发、脸型、袖口和对称垂带本身已经不同。仅修改眼睛，或仅校准部件框，均不足以恢复设计。

- `9200efa5c9e40b6f573c41111fc6fbb2811513b6`：登记两张用户设计原图与摘要，以共同脚底和统一缩放转换母版坐标；共享五官、关节、足底及静态网格补偿，增加设计叠加和独立生产轮廓检查。
- `50bcfec1a6bdadeff46ce20ebf68bebd8eb9ef68`：按资源表 D1-C07 使用内置 image_gen 重制分层稿。v4 仍受旧图集造型影响，v5 的矩形裁切间距不足；选用 v6 的正面／右斜后，恢复长后发、短前发、长袖、围裙与非对称腰结。侧脸遮挡和去尾根回钩继续保留。完整原图、提示词、参考链、候选状态与摘要见 `source/faithful-revision-v1.json`。
- `a76f53b6b36e1b62e7d14d9e3a0595fdd6ab585d`：新素材增加了对应源码下载的同步重复压缩开销。对已压缩媒体采用 ZIP 原样存储，其他源码继续压缩；回归检查两张运行 PNG 解包后与源文件逐字节相同。该提交只改 `src/figure-server.ts` 和 `tests/figures.test.ts`，角色运行代码与素材和 `50bcfec` 相同。

原始素材及旧证据均保留；仅移除运行导出目录中已被替换、与源稿逐字节相同的三份旧 PNG 副本。当前导出为 6 个文件，旧候选不再随默认方向身体加载。未引入 Cubism SDK 或平台专用渲染；交付仍是现有 WebGL 网格的 Live2D 式分层身体，不是 `.moc3`。

## 遇到的问题与边界

1. 只校准旧拆件后，轮廓指标已能通过，但实际发束、袖口和腰结仍不同，因此继续制作 C07，而没有以数值代替人工并排复核。
2. 新分层稿的部件视觉分离不等于矩形 UV 可分离；v5 的脸／前发、裙／手臂边界会互相污染。v6 调整图集留白后才通过源图裁切检查。
3. 在沙箱内扩大测试时，诊断采样的系统进程读取失败；在正常主机权限下通过。原全套测试另两次因源码打包超过 5 秒失败；计时确认主要在源码压缩／解包，修复后按原命令、原门槛通过。失败日志与计时记录保留。临时诊断测试副本曾被通配发现，随后移为不可执行文本；最终通过日志不含该副本。
4. 本次并非逐像素复制：补画和生成线条、颜色仍有细节差异，五官与蓝金结继续复用原图层。对照只覆盖用户给出的两个方向，正背面与原斜前不冒用此结论。坐卧、持物、手势及其他配色仍走已有兼容身体。
5. 本轮没有运行完整 `test:desktop`，也没有新做 Windows／Linux 原生、物理多屏／DPI 或用户长期 LIVE 验收；不能以 VM 和自动化结果结算这些体验。VM 结果取回后正常关机，已确认基线／测试机均停止。

当前实现、资源表和使用说明已同步；后续针对实际设计叠加反馈继续精修可见细节，执行范围由用户最新要求决定，不把本报告变成自动进入下一阶段的指令。
