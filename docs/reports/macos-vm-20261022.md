# 2026-10-22 macOS 测试机验收

此报告记录该次虚拟机配置与自动化验证，当前使用方法见[隔离测试机](../macos-vm-testing.md)。不作为后续源码测试、用户体验或物理设备验收。

## 环境与容量

- 宿主：Mac mini M4 Pro、24 GiB 内存、macOS 15.8.1；没有升级宿主或安装 Softnet。
- Tart：官方 2.40.1 完整 app，归档 SHA-256 经 Homebrew 官方配方摘要核对，签名检查通过。
- 来宾：macOS 15.7.7（24G720）、4 vCPU、8192 MiB 内存、1440×1080 虚拟显示、80 GB 稀疏磁盘。来宾 APFS 卷已扩展，首次工具链准备后约 45 GiB 空闲。
- 镜像固定到 `ghcr.io/cirruslabs/macos-sequoia-base@sha256:eee659985b01e4df2a6c0754bd8d25e54969933c43fdcd4edef8bea337b3d354`，下载约 23.7 GiB，没有使用 Xcode 大镜像。
- 单个固定 OCI 镜像、准备基线和测试克隆均位于项目独立 Tart home，两个本地 VM 最终均正常停机；重启、SSH 重新连接及标准停止入口验证通过。

宿主可用空间从 **150.84 GiB** 变为 **112.84 GiB**，净减少约 **38.00 GiB**（该全盘差值也包含同期其他宿主写入，不能精确归因于单目录）。VM 目录 du 累计约 **88.27 GiB**，其中 APFS 镜像／克隆共享块会重复统计，不能当作独占分配相加。80 GB 是每个来宾磁盘的逻辑容量，并非启动时立即消耗 80 GB。

按约 30–45 GiB 的初始增量和 50–60 GiB 准备峰值估算，当前余量足够。启动入口检查宿主至少 60 GiB 空闲，保护单实例及项目存储路径。宿主的休眠、共享硬件负载和磁盘后续增长仍影响 VM；该配置不承诺性能完全隔离。

## 双向隔离与身份

默认 NAT；不打开宿主 VM 窗口，不共享宿主目录、剪贴板、音频或 USB，不登录日用 Host／Apple 账号。专用 SSH 密钥与 known_hosts 仅保存在项目本地目录，严格核对服务器身份，不转发 SSH Agent。来宾由 Guest Agent 配置公钥和独立 SSH 主机密钥，密码／键盘交互 SSH 认证关闭；真实控制台用户和 gui/501 会话均为 admin。

Node 24.21.0、npm 11.19.1 以核验过的宿主工具链输入一次性传入准备基线；项目依赖在来宾按 shrinkwrap 安装，Electron 与一套 Playwright Chromium 1248 在基线准备并供克隆复用。再次 setup:browser 没有重新下载。宿主没有复制整套项目 node_modules 到各阶段；一次性源码导出及工具链传输包在完整副本核对后移除，保留项目专用身份和 VM 磁盘。

最初源码为 `71abca6`，原生窗口探针和键盘检查在该版本通过。完整 npm test 首次暴露缓存清理器丢弃 lsof 部分 PID 输出的问题；复现后增强活动目录回归并修正，固化为 `c7a6e327d5986bdf6f8442a586f083e403d50653`。工作克隆和准备基线最终均切换至该提交，Git 工作树干净。

UI 与原生角色回归期间使用 `71abca6` 加同一缓存保护补丁的工作树；最终清洁重建确认产品输入摘要保持 `26785e614a14fc0f7ce1c6498ae9fd15c07d3e3b0c46c0e8ecfa72c590bb0208`，未把旧 build-info 的提交字段伪装成新提交结果。
