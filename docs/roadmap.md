# 桌面伙伴改进路线图

更新：2026-10-15。实施基线：v0.4.8，源码 `e151a83653f2851bec52edb9347bb5b7255a44a8`。支持范围沿用 DSH 0.2.0-rc.2 和 0.2.1-alpha.1。

目标是让角色陪伴、会话交流、结果阅读和待办提醒更准确、顺手。优先核验完成语义，再补齐会话续接、异常恢复与文字可读性；多屏和日常陪伴节奏按进入条件推进。M1、M2 已完成实现与本地验收，待维护者审阅；M3 已完成实现与本地验收，跨平台退出条件待验证；M4 已完成实现与本地验收，待维护者审阅及外部平台验证；M5 已形成实现，正在本地验证；M6 未启动。

## 产品目标与现有优势

- 保留 Coopanion API 2 的实时网格、表情、视线、说话脉冲、物理互动和角色包沙箱；动作通过角色声明的词表调用。
- 用户明确选择聊天会话，输入进入 Harness 的持久会话，沿用其模型、工具和权限；后台活动不抢占关注会话。
- 回复收件箱保留完整结果、按会话合并未读、支持继续交流和返回来源；阅读中的正文不被新结果替换。
- 角色显示时以角色呈现提醒，隐藏时按设置选择系统通知。查看、标记已读与实际审批或答复分别结算。
- 摸头、换装和闲时动作保持本地交互。测试以隔离 profile、正式宿主加载和 CI 为主，系统实机验收单独记录。

当前行为见 [README](../README.md)、[角色接口](characters.md)和[提醒契约](notification-contract.md)。已交付通知阶段由[原执行计划](notification-plan.md)保留历史记录；新增行为和状态以本路线图逐项交付。

## M1 完成语义

### 工作与接口

当前 [PetModel](../src/model.ts) 在 `turn/end: completed` 时庆祝，[NotificationBroker](../src/notification-broker.ts) 将其转换为完成提醒，尚无目标级终态判断。目标自动续跑时可能提前报喜，先通过正式宿主重放确认。

1. 在两版隔离宿主内核对目标事件或公开投影的精确 schema、目标 ID、revision、状态、消息来源以及与回合结束的先后关系。现有依赖可见 `goal/change` 事件名及带 `goalId`、`revision`、`round` 的 goal 消息来源，但这不足以确定完整生命周期。首个交付物是版本对照表、实际事件样本和可重复检查命令。
2. 固定普通回合、目标进行中、目标完成、阻塞、停止及未知状态的展示和提醒规则。覆盖首次用户回合创建目标、自动续跑、目标更新和同会话多个历史目标；按完整身份与已提交顺序关联。
3. 在 Host 增加共享的完成判定模块，供角色状态和提醒生成共同消费。确认的目标终态来自公开投影或已提交状态；工具调用参数不作为操作成功的证据。
4. 中间回合仍保留最终回复及现有未读规则，不庆祝为目标完成。目标状态无法可靠取得时使用“本轮回复已生成”等回合级措辞，继续提供结果、异常及待办入口。目标阻塞与错误分别按实际状态呈现。
5. 核验若需要扩展提醒类别或共享消息，先更新 [notification-contract.ts](../src/notification-contract.ts) 及契约文档，确定旧配置和历史恢复行为，再接入呈现。

### 文件与验收

2026-10-15 本地验收完成，实施与完整证据见 [M1 契约与验收](evidence/m1/README.md)：已确认首个人类回合创建目标、3 轮自动续跑、失败更新无提交、目标完成先于最终回合结束，以及 round-limit 阻塞晚于回合结束；两版公开 schema 一致。实现提交 `df36f0dd138c48cac491a552bba3e1950dc48184`，120 项 Vitest 与 12 项 Node 检查、相关浏览器/macOS 原生检查、同一产物的两版正式安装均通过；远端三平台 CI、真实模型和系统通知中心验收未执行。共享判定复用宿主严格目标折叠，普通与中间回复不庆祝，保留全文和未读；只有新目标的已提交 complete 才庆祝。

实施范围：`src/model.ts`、`src/notification-broker.ts`、`src/notification-contract.ts`、必要的共享判定模块和 `src/index.ts` 装配；Client 文案及角色映射按契约同步。复用 `tests/model.test.ts`、`tests/notification-broker.test.ts`、`tests/notification-integration.test.ts` 和正式宿主检查入口。

- 普通单轮完成、中间续跑、目标成功、阻塞、停止和缺少目标服务均有确定结果；目标更新调用失败不会触发成功。
- 角色、托盘、回复文案和系统通知使用一致判断；中间结果仍能阅读和继续交流。
- 重复事件、迟到事件、重启折叠、并行顶层会话与子代理过滤通过；恢复不重放旧通知或增加旧未读。
- 审批与限时提问的 open / continued / settled 状态、补提醒和已读逻辑保持独立。

退出条件：两版宿主契约与受控重放通过，随后相关单元、界面和安装检查通过。若公开能力不足，交付明确的回合级措辞和能力边界，不猜测目标完成，也不无限等待目标状态。

## M2 会话直接续接

### 工作与接口

[聊天入口](../src/index.ts) 已改用正式 `sessionController` 提交普通会话消息。两版实际契约表明：冷恢复与完整请求身份可用，但已领取间隙的重试及并发准入会重复写入；Host 已用串行准入与持久收件记录复核补齐。共享线协议与 UI 状态见[会话续接契约](session-chat-contract.md)，完整样本与本地验收见 [M2 记录](evidence/m2/README.md)。参考 [dsh-orb 的会话实现](https://github.com/mini-yifan/dsh-orb-cordis/blob/e5611a1b905091a48e32e25d183ef6ef9517d4ab/packages/host/src/orb.ts#L682)。

发送协议携带固定的 `sessionId`、客户端生成的 `requestId`、文本和用户时区；一次提交重试复用同一个请求 ID。Host 限定普通可续接会话并复核身份，沿用当前文本限制和 `mode: queue`，通过正式服务恢复目标会话。不可用、已删除、被其他进程占用或权限受限时反馈具体原因，不改投其他会话。

输入框显示发送中、已接受或失败。提交时固定目标，切换关注会话不改变在途目标；未获得接受回执时保留草稿。Host 对并发提交和重试去重；接受消息仅表示进入目标收件队列，任务结果继续由 Harness 事件驱动。

## M3 桌面异常恢复

实现与共享线协议见[恢复契约](desktop-recovery-contract.md)，完整包身份与事件样本见 [M3 本地验收](evidence/m3/README.md)。实现提交 `15abf97f3b3522c648f7bd8b69f9e095f3a3c664`；142 项 Vitest 通过、1 项仅 Linux 检查在 macOS 跳过，12 项 Node 检查、浏览器和 macOS 真实进程恢复通过；同一固定包在 DSH `0.2.0-rc.2` / `0.2.1-alpha.1` 正式安装通过，保留 M1/M2 契约与持久身份。版本保持 v0.4.8，不推送、不发布；远端 CI、Linux/Windows 原生、物理锁屏/休眠、真实模型与物理通知中心仍待验收，三平台退出条件尚未满足。

### 工作与接口

在现有 [PetControls](../src/controls.ts) 和 [ElectronBridge](../src/bridge.ts) 上增加有限退避，复用启动取消、清理期限和 generation 隔离。首次实施采用最多 3 次自动恢复，间隔 1、3、10 秒，连续稳定运行 60 秒后清除失败计数；时间参数可注入测试。

仅对意外退出和明确可恢复的启动失败重试。缺少图形环境、无效运行时路径等确定性问题直接反馈。停止、停用和卸载立即取消在途启动与重试；达到上限后保留诊断及手动重启入口。

将用户期望的显示状态与原生可见性回执分开管理，恢复时按原显示意图初始化，隐藏状态不闪现窗口。新进程就绪后发送 Host 最新会话、结果和请求快照；恢复不重跑任务。通知资格仍按新的原生回执和 generation 判断。

## M5 多屏适配

进入条件：M1 至 M4 已验收；整理至少一组不规则布局与一组混合缩放的实际问题或受控复现，并确定对应原生验证环境。

2026-10-15 按用户明确要求从 M4 本地验收继续。M1–M4 的本地证据已齐，维护者审阅、远端 CI 和其他平台尚待验收，M3 三平台退出条件仍未满足。已固定上方竖屏切屏遗漏与混合比例负原点的受控复现，原生环境为 macOS arm64 / Electron 44.7.0、单块 P272U PRO（2048×1127 DIP，scaleFactor 2）。共享坐标、显示器身份及状态保持规则见[多屏契约](multi-display-contract.md)，执行证据见 [M5 记录](evidence/m5/README.md)；受控布局不代表物理多屏 / 混合 DPI 通过。

先抽出可注入显示器布局的几何逻辑，覆盖负坐标、上下错位、竖屏、任务栏条带、工作区空洞、拔屏和缩放变化。参考 [dsh-pet 的区域测试](https://github.com/PC2005-cloud/dsh-pet/blob/7f507e20e5b4f64cc9d51a44454ba13b13e789cd/dsh-pet/src/shared/displays.test.ts)及 [dsh-orb 的面板几何](https://github.com/mini-yifan/dsh-orb-cordis/blob/e5611a1b905091a48e32e25d183ef6ef9517d4ab/packages/helper/src/geometry.ts)。坐标转换按平台核验，不直接复制强制设备缩放参数。

首批交付保证每块屏可用、切屏后面板可见、拔屏后角色回到有效工作区、文字缩放后的命中区域准确。跨屏自由漫游、抛掷和贴边休息在这一基础通过后再确定范围，不把现有角色物理系统整体替换。

实施范围：`desktop/main.cjs`、`web/pet.js` 的工作区与锚点逻辑、必要的几何模块及 `tests/desktop.mjs`。纯几何检查必须可在 CI 重放；混合 DPI 的原生坐标与点击结果单独验证。退出条件是已确定布局均能定位、阅读与点击，拔屏恢复后无不可见或无法操作的角色与面板。

## M6 日常陪伴节奏

进入条件：M5 已验收；确认闲时活动的频率与安静时段确有体验需求，并先记录现有待机资源开销。

在已有 calm 漫游和动作去重基础上增加可选的时段策略，首批仅用现有词表实现白天、夜间的安静程度和活动间隔，默认关闭。以注入的本地时间、随机源和占用状态选择动作；任务、待办、阅读、输入、拖拽、用户休息和减少动态效果设置优先。角色缺少相应动作时保留现有待机。

参考 [Big Blue Fish 的纯动作策略](https://github.com/Bai-Cute/big-blue-fish-desktop-pet/blob/63e60cee15c2e0f12a5cb47ce7c6f62b7b9b33fa/code/BigBlueFish.Windows/Companion/CompanionAnimationPolicy.cs#L33)，不引入模型请求、前台内容采集或新的节日素材依赖。实施范围为宿主可控的行为策略、`web/pet.js`、偏好设置及相应测试，继续经 API 2 驱动角色。

退出条件：可控时间验证跨日与时段变化、忙碌时让位、动作结束后恢复及配置持久化；确认不会覆盖任务神态、增加通知或显著恶化待机开销。资源预算在进入本项时根据同环境基线确定。

## 后续候选

- 角色制作体验：沿 `examples/star`、`character:pack` 和现有预览补充创作教程及视觉检查，不另建角色格式或视频引擎。

候选项不阻塞 M1 至 M4；进入实施前补齐范围、文件归属和退出条件。

## 验证与交付

实施者为当前里程碑维护一个可独立审阅的提交序列，记录本轮场景、命令、结果和剩余边界；维护者据此验收后推进状态表。跨模块规则先固定共享契约，再顺序接入 Host、Client 与桌面，避免多处各自判断。

| 检查层 | 执行方式与完成条件 |
|---|---|
| 局部检查 | 使用可控事件、时钟、随机源和显示布局验证当前里程碑；先运行相关测试 |
| 集成检查 | 修改入口、消息或配置后执行类型、单元、构建及对应浏览器或桌面检查；沿用现有 CI 的三平台与两版宿主矩阵 |
| 正式安装 | 实际 `.tgz` 经官方 profile loader 安装；宿主接口检查在正式 Host 内执行，记录两个完整版本及包摘要 |
| 系统实机 | OS 通知身份与留存、物理混合 DPI、真实模型等仅按实际覆盖结果验收；受控通知适配器和虚拟显示不能替代 |
| 发布 | 功能验收后同步 README、契约与版本记录，按[现有发布流程](releasing.md)处理版本、CI 和分发产物 |

每次里程碑记录绑定完整源码提交、宿主版本及实际产物摘要。当前路线图的本地提交仅交付计划；功能实现、CI 验收、版本变更与对外发布分别记录，继续保留既有系统实机验收边界。
