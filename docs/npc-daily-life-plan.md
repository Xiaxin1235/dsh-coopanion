# NPC 日常与有限空间：能力评估和修订方向

核对：2026-10-16。用户已认可本页的首步体验方向；**首步修订已实现于本地源码，未发布、未更新日用安装**；具体行为与参数以[陪伴契约](companionship-contract.md)为准。旧 0.4.10 包仍运行原行为。发布／候选身份和验收状态见[文档索引](README.md)，P2 偏好养成与 A1–A3 素材线没有因此实施。

目标：**从小窝出发，在有限空间内观察、移动、停留，遇到用户操作时退让，之后继续自己的安排；忙碌时收缩空间、降低表达，空闲时恢复探索，始终保留自己的日常状态。**

## 现有能力是否足够

结论：现有鲸鱼的动作和表情足以制作第一轮完整循环，无需先生成新角色或扩展物件。主要缺口在宿主的空间约束、意图调度、输入感知与打断恢复。音效能够复用，但默认安静的视觉体验必须独立成立；现成的实体小窝和可交互道具尚不存在。

| 类别 | 已有能力及来源 | 首步使用方式与限制 |
|---|---|---|
| 移动 | [鲸鱼清单](../web/upstream/whale/figure.json)声明 `can.walk=true`；[body](../web/upstream/kit/body.js) 与[沙箱桥](../web/upstream/body-host.js)提供 `walk(x, run, id)`、`stopWalk(id)`、`arrived`／`interrupted` | 使用慢走和显式目的地，沿当前工作区底部移动。它是沿地面的一维移动，不是任意二维寻路；跑步、跳跃、抛掷不作为自主探索手段 |
| 姿态／动作 | 清单有 18 个 motion，包括 `stand/turn/look/nod/sit/sleep/wave/dance`；sit、sleep 是持续姿态 | 组合“起身—看向—走到—观察—停留—返回”；坐下／睡眠要显式起身，不能套用统一秒数就当作安全结束 |
| 表情／细节 | 清单有 19 个 expression；[鲸鱼绘制](../web/upstream/whale/figure.js)支持视线、眨眼、脸部、身体／发尾等变化；body 支持短暂 `do` 和持续 `set({expression})` | 首轮选择平静、思考、开心、困倦，辅以观察和转向。没有公开 `curious` 词，使用 thinking＋look 表达好奇；声明数量不等于用户已经能辨认全部表情 |
| 音效 | [sound.js](../web/upstream/sound.js)有脚步、观察、点头、表情、跳舞、触摸和呼噜等 Web Audio 合成，支持总开关、音量及按类静音 | 鲸鱼清单 `sounds={}`，没有独立录音素材。可以复用合成音；忙碌时抑制自主动作音、邀请和装饰性气泡，保留用户原音效偏好及任务通知规则。音频需解锁／可播放条件，不能靠声音作为唯一反馈 |
| 物件／小窝 | 当前鲸鱼只有 8 套配色，未提供窝、床、玩具、食物或可交互家具系统；已有爱心／音符／睡眠等粒子 | 第一轮“小窝”是用户可调整的安全归属点，可补一个轻量、点击穿透的程序绘制标记；本轮使用程序标记，不声称已有实体窝。道具继续走素材线 |
| 缺词角色 | [纸星星示例](../examples/star/figure.json)有 walk、stand、sleep 等较少词表，复用 kit | 能力逐角色核对，缺 look／sit 时降级为停留／已有表情，不能强发词；纸星星是角色示例，并非鲸鱼可拿起的玩具 |

`walk`／`stopWalk` 在 API 2 中是可选能力，代理对象提供同名方法不证明自定义角色实现了它；需结合清单、实际回执和有界超时降级。`stopWalk(id)` 也不是通用动作取消，短手势可能要自然收尾，空中／拖拽必须保留原物理拥有权。

源码能力与隔离浏览器探针见[评估记录](evidence/p1/npc-capability-20261016/README.md)。探针只验证现有原语与渲染／音效请求，不证明新的日常循环、原生键盘感知、真实扬声器播放或体验通过。

## 第一轮世界与活动空间

感知范围限定为当前显示器工作区、角色位置、鼠标位置／距离、键盘活动、昼夜、DSH 工作事件及用户与角色的互动。键盘只向策略提供“最近是否输入／是否可判断”，不保存字符、按键序列或组合键，不读取屏幕正文、输入框位置或其他应用内容。

小窝设在当前屏幕底部靠左或靠右的安全位置，活动区是邻近的一段地面。用户能调整位置和范围；随尺寸、工作区或显示器变化重新校准，按角色实际外接矩形留足边距。首步不跨屏探索、不改变整个窗口工作区来伪造活动区、不沿窗口标题栏行走。

小窝位置与活动区使用新增持久设置 npcHome／npcRange，采用相对工作区的约束；不依赖旧全局坐标或跨重启显示器 ID。安全区仍可能覆盖正文，提供临时收拢／隐藏和重新定位入口。仅靠键盘活跃信号无法承诺精确避开文本插入点。

## 日常状态与意图

运行期保留当前兴趣目标、探索阶段、最近去过的位置、精力／兴致、当前情绪及短期记忆。忙碌事件改变可行动范围和表达强度，不清空这些状态，也不把没被回应解释成关系惩罚。跨进程、跨角色和存档边界继续遵守现有契约；不新增离线探索结算。

| 阶段 | 可见表现 | 后续安排 |
|---|---|---|
| 小窝停留 | 眨眼、张望、短暂坐下，形成稳定归属 | 从近期没去过且安全的位置选择兴趣点 |
| 准备出发 | 起身、转向、观察目标方向 | 走向有限范围内的目的地 |
| 探索途中 | 慢走，方向和目标保持连贯 | 等待实际 arrived，不按固定时长假定抵达 |
| 抵达停留 | 观察、点头或短暂愉快，再安静待一会儿 | 继续下一处、休息或返回小窝，不以连续跳舞代替内容 |
| 忙碌退让 | 停止扩大活动，在小窝附近安静观察或休息 | 保留未完成意图；外部占用解除且稳定后重新评估 |
| 恢复探索 | 先观察当前情况，再继续仍有效的安排 | 目标失效时合理重选，不重播中断动作或补播错过事件 |

情绪是上述经历的缓慢结果，先用少量现有表情表达。任务表情与 NPC 情绪分别拥有状态，由呈现层仲裁；新工作获得关注后，NPC 状态仍在，恢复时能接续。首轮固定时长与恢复等待见陪伴契约；这些工程参数尚不代表用户主观体验通过。

## 用户操作时怎样退让

- 鼠标进入行进路径或角色附近的操作区域：先停止本次移动，不追逐鼠标；退避有冷却，防止反复追逃。用户主动点击、拖动或打开角色面板时尊重其操作，不抢回控制权。
- 持续键盘活动：停止外出和主动邀请，收紧活动范围，降低自主动作、音效与气泡表达。短暂停顿不马上出发，连续按键不反复重置全部状态；稳定空闲后平缓恢复。
- 已处于妨碍操作的位置：优先停止并让出视觉／点击区域；只有路线安全时才慢走回去，必要时通过角色自身 bounds 临时收拢。不会要求它横穿正文跑回小窝。
- 新任务、审批或异常：按现有正式事实呈现工作与待办；活跃操作期间安静退让。已经呈现的长期待办保留入口，可允许小窝内低干扰日常继续，不改变待办结算、提醒领取、完成判断或已读语义。
- 隐藏、锁屏、休眠、减少动态效果及用户选择休息：保留原有控制意图；暂停自动探索，恢复时核对时间与几何，不追赶活动。临时视觉收拢与用户主动隐藏必须区分，避免误改系统通知资格。

“忙碌”由感知和占用仲裁统一生成，分为可探索、安静日常及暂停／用户接管等明确状态；工作中的安静日常不覆盖任务表情、用户输入或阅读。可观察、可移动、可邀请、可播放自主音效分别判断，避免一个布尔值把所有生活感长期关闭。

## 本轮实现对应的宿主缺口（设计依据）

1. **感知适配。** 现有原生鼠标坐标／显示器几何和 DSH 事件可以复用；跨应用键盘活动本轮加入 macOS 聚合时间、Windows Raw Input 通知和 Linux X11 类别适配，Wayland 保守 unknown。按平台验证实际能力与权限，返回 unknown 时采用靠边安静策略，不能将系统总空闲时间直接说成已能识别打字；不阻止原始键盘事件。
2. **空间与日常决策。** 在现有纯策略边界内形成完整意图，加入小窝、活动区、兴趣点和退让／恢复；复用已有精力／兴致，原生层提供环境事实，角色包只执行与绘制。
3. **动作拥有权。** 定点移动使用非零、逐代绑定的 walkId；停止只取消自己的移动，迟到 arrived／interrupted 不推进新意图。[onBody](../web/pet.js)现已消费匹配的行走事件；自身 moving 不视为外部占用。
4. **表现仲裁。** 本轮关闭旧自由漫游与自动片段，改用保留意图的新调度。任务表情、NPC 情绪、姿态、音效及阅读／输入各自保持身份与优先级；热更新保留 frame、草稿、捕获正文和在途请求。现有音效回调仅有名称／类别，本轮宿主按自主动作拥有期分流，并让用户互动与工作提示优先；不关闭总音效开关。
5. **最小小窝标记和诊断。** 增加锚点／范围配置与轻量标记；诊断补充固定枚举的意图阶段、暂停原因、输入活跃／unknown 和目标有效性，便于自动解释长时间静止，不采集键盘内容或要求用户填表。

默认自主模式与用户总许可保持兼容，设置文案需要明确“允许自主活动”与“探索范围”的关系。本轮持久字段、固定参数和平台边界已同步陪伴契约与 schema；以下设计依据不替代现行实现契约。

## 实施与验收顺序

先验证输入感知和受控行走的可打断性，再接入一个完整的“出发—抵达—观察—退让—恢复／返回”循环；之后调整表现。保持当前固定上游版本，首轮不依赖新角色、录音或道具制作。

| 检查 | 首轮完成条件 |
|---|---|
| 可见日常 | 工程侧短时场景中能直接看出出发、目的地、停留和返回；用户自然反馈能否感到连贯与生命感，不设七天／评分表 |
| 不妨碍操作 | 持续输入和鼠标操作时收紧范围、停止不合适移动／邀请；停顿不反复探头，显隐与点击穿透正确；不抢焦点 |
| 状态连续 | 忙碌前后的兴趣／情绪有因果衔接，目标失效可重选；旧回调、任务插入、休眠和角色切换不重放或串代 |
| 能力降级 | 鲸鱼和缺词角色分别验证；无移动能力时保留原地日常，键盘未知时保守安静，静音时仍能理解行为 |
| 既有功能 | 阅读、草稿、选区、在途请求、目标完成、通知身份与领取、用户休息、几何和沙箱回归通过 |
| 资源与平台 | 新实现重新做同包短时对照及长时观察；键盘／鼠标和原生行为逐平台验证，旧候选的 VM 结果不能外推新方案 |

本页保留已确认方向与能力评估；上述宿主缺口已进入本轮实现，行为以陪伴契约为准。工程测试、候选身份、物理系统验证与用户主观体验分别结算。旧候选体验未通过，不能将本轮源码实现写成体验验收通过。
