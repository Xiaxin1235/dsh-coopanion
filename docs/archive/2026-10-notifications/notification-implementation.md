## 身份与投递

事件提醒保留 N0 五项 JSON 元组。稍后提醒的调度轮次作为可选第六项；运行中的无日志问题使用完整 runtime 请求 UUID 作为第六项，调度轮次作为可选第七项。`source: runtime` 明确区分运行请求与日志事件，turn／seq 表示其已提交上下文锚点。

公开 timed 提问使用完整 callId 与原始 tool/call 或 ptc-dispatch 事件配对。continued 请求保留到公开投影结算；打开和阅读不结算请求。无 callId 的运行请求在取消或原 answerer 完成时结算。

系统领取一旦发出便占用该提醒的通道。显示切换、挂起、过期和断连将无法确认的投递记录为 unknown，保留迟到真实回执及待处理入口；新的补提醒或稍后提醒使用独立调度身份。角色投递使用当前原生 generation 与 visibilityRevision 再次核对。

用户测试通知通过 Host 的公开 sessionController.create 创建可导出的源会话；同一插件生命周期复用该源会话，测试回合产生新的完整提醒身份。只有角色运行且隐藏、独立开关开启时才领取。权限、requested、shown 和 Host 接受回执分别显示。

## 会话收件箱

采用已确认的“先看回复”交互：信封与托盘的待查看入口共用收件箱，汇集待审批／提问、异常及实时未读结果。仅有一份未读回复且没有其他待办时，直接展开完整回复；多份结果显示源会话、摘要与各自的继续对话按钮。阅读不会切换聊天对象，直接跳转绑定具体结果的源会话；列表预览和收起面板不确认未读。收件箱阅读支持按打开时的顺序连续读不同会话的结果，新结果留在收件箱，不替换当前内容。使用现有角色气泡描边、尾巴、配色和定位，保留输入、阅读及拖拽期间的提示保护。

本地检查通过：93 项单元／集成、11 项构建／发布检查、两套类型检查、`tests/inbox-ui.mjs`、现有通知和角色浏览器回归、原生桌面回归。收件箱检查覆盖单次打开全文、准确源会话跳转、混合待办、未读确认、跨会话连续阅读、键盘焦点、双语与窄屏；原生检查覆盖真实 IPC 的单份后台回复入口与跳转。窗口尺寸改变后等待角色的新几何再重新锚定气泡，修复面板尾巴与桌宠脱离的问题。长结果的列表更新仅比较身份与时间，避免流式动画期间反复扫描全文。

已将收件箱浏览器回归加入三平台 CI；本轮未执行远端 CI 或正式宿主安装矩阵。界面截图位于本地 `artifacts/session-inbox.png` 与 `artifacts/inbox-narrow.png`。
