## 结论与定位

问题发生在原画到分层、分层到绑定、以及验收三个环节。现有实现是自有 WebGL 网格与变形树，属于 Live2D-like 技术，没有走 Cubism PSD → cmo3 → moc3 的制作／导出链。沿用引擎可修这些缺口；更换引擎不会自动恢复被重绘改变的角色。

| 现象 | 已核对事实 | 结论／边界 |
|---|---|---|
| 转向后像另一个角色 | 正背面仍用 `back-atlas-v2.png`；正面、斜后用独立生成的 faithful v6；斜前保留原模型。正背面没有本轮共同设计坐标注册。v6 又经过一次生成来缩小图块、增加间隔 | 多套独立重绘混用，缺少统一转面验收。单张外轮廓接近不能证明头部体积、脸颊包络、发束与五官属于同一角色；身份判断仍需可见审阅 |
| 斜后尾柄看起来接错位置 | 当前尾巴 `z=1`、裙身 `z=4`，腰结 `z=10.1`。在设计坐标 `(400,1150)` 应出现蓝色尾柄，实际读到白色裙边；只把尾巴层级改为 8，蓝色尾柄重新出现 | **绘制层级错误已用真实渲染复现。** 只改层级能恢复这处遮挡，但候选尾柄的轮廓／颜色仍与设计不同，不能据此宣布尾巴完全修复 |
| 可能随摆动发生相对位移 | 尾巴独立绕手写 pivot 旋转，裙身使用另一组 warp；没有部件原图尾根与身体尾根的一对对应点、覆盖范围和连接约束 | 缺少可验证的连接契约。尚未证明这是用户所指静态错位的主因；不要把推测写成已经定位 |
| “中性零姿态”仍与原画不同 | 时间为 0 时仍使用 restWarps，部分 `sin(u)`／`sin(v*2)` 位移并非 0；清空全部变形后尾柄遮挡仍失败 | 时间归零不等于关闭变形，需独立静态拼合模式；这不是遮挡问题的唯一来源 |

网格把每个 UV 矩形独立拉到目标矩形。原画的统一比例只保证目标框的坐标换算；它不能保证重新生成的图块内部比例、附件位置与原画一致。用额外静态 warp 抵消源稿偏差，会让“原画、默认形状、动画变化”难以区分。

## 纠正后的制作顺序

1. **统一角色转面母版。** 当前先在同一画板检查正面、真实侧面、斜后、正背面；侧面用于暴露裙下出尾与尾鳍平面的矛盾。固定身高、头部体积、发束走向、鳍／头饰的角色左右、腰线与尾根；其余产品方向在母版稳定后补齐。原先要求的遮脸和去钩先落在母版上，避免拆件阶段临时改角色设计。没有接受的方向仍是候选。
2. **保留可见原画再拆层。** 从对应母版复制可见像素，用可编辑蒙版分离部件，补画放在独立层，仅补运动会露出的隐藏部分。保持统一画布和原始位置。图集打包只改变存储位置，必须保留原画偏移及 UV 映射；不能调用生成器“重新画一张拆件图”或“缩小每个部件”来替代裁切／打包。工具不能保证可见区不变时，输出继续视为重绘候选。
3. **先通过无动画拼合。** 禁用呼吸、视线、眨眼、物理、静态补偿，把各层原位合成并与锁定母版比较。分别看头脸、发束、腰结、尾根，不只算全身 alpha 重合度。差异必须对应已登记的设计修订；不以拉伸或 warp 修补另一套画风。
4. **再绑定连接和遮挡。** 每个部件记录原画坐标、旋转中心、身体连接点、遮挡补画边界和前后关系。尾根共用身体的连接事实，只让远端摆动；前后视角分别记录尾巴与裙、腰结、头发的遮挡。独立画布框不能充当连接点。
5. **逐项加动作。** 先尾巴一个动作，再呼吸、手脚、头发；检查正常、慢放、极值和逐帧。连接处的实际绘制结果、方向切换与用户对角色身份的判断分别记录。通过一个方向后再推广，避免一次替换多方向后无法归因。
6. **最后接入产品。** 复用现有身体与导航，验证默认渲染和制作台一致，执行要求的 UI 与 VM 回归，再核验分发包。自动化通过与美术放行必须是两个不同状态。

这与 Live2D 官方的[素材拆分流程](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)一致：复制源图、用蒙版分离、在新层补画，并保留可继续编辑的拆分稿。其 [PSD 说明](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/)列出 Photoshop 与 CLIP STUDIO PAINT 作为已验证导入工具。我们可采用 PSD 分层原稿，或保留等价原画坐标／蒙版的分层源；当前“独立重绘 PNG 图集＋绑定 JSON”不具备这项保真保证。

|---|---|---|

| D1-R02 | 从锁定母版保留原画坐标的分层源 | 可见区域不重绘；补画与原画可分离；静态拼合能回到母版 |

| D1-R04 | 静态拼合与局部对照工作台 | 真正关闭全部变形、局部放大与连接点显示；保留当前失败样例作为反例 |
| D1-R05 | 单方向动作及完整方向推广 | 单变量通过后推广；最后运行产品／浏览器／VM 回归及用户观感验收 |

优先交付 R01 的统一静态转面；R04 可以独立准备，但不能替代母版接受。新原画或补画仍遵循资源先行、完整提示词／参考／原图保留的流程。旧素材及历史报告保留；当前状态明确拒绝美术放行，不让后续 agent 按 `selected` 字样推断用户已认可。

这些改进位于资产与共享 WebGL 制作层，不引入 macOS 专用依赖。三平台运行验证仍按既有平台门槛分别结算；不以 macOS VM 证明 Windows／Linux 已验收。
