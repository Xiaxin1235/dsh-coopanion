## 最新体验结论与基础缺口

2026-10-22 用户体验反馈指出：活动仍主要位于屏幕下方，拖高后仍会下落，人物只朝左／右，二维空间和面向用户的表现缺失，与 main 的可感知差异有限，尚无足够 LIVE 感。当前默认产品的空间与身体体验未通过验收；旧自动化和工作台验收保持其原范围。

原反馈基线的默认目标集中底部、拖放下落；D1 首个切片已改变这两项行为，身体朝向仍为左右镜像。完整问题、证据位置、影响和建议验收集中在[空间与身体复核](design/space-body-review.md)，后续接手必须先读该页。该页明确区分已实现能力与待实施目标。

## 验证与运行边界

浏览器使用真实 WebGL、导航、接触和存档，但输入与工作事实受控。隔离原生使用真实 IPC、OS 鼠标和系统键盘适配器；部分有界恢复测试控制输入枚举，不能替代物理键盘验收。四版本真实模型、物理多屏、三平台 CI、长期资源、日用安装和用户体验各自结算，固定报告不代表本轮重新测试。

当前 Linux CI 使用 Xvfb＋Openbox，只证明其 X11 场景；Wayland／Xwayland 的键盘输入当前为 unknown。Windows 原生键盘检查允许记录不可用状态，不能据其通过推断交互桌面输入已经可用。新增专项必须补齐正向能力与会话验收，不用本机 macOS 结果代替其他平台；具体门槛见[跨平台方案](design/desktop-environment-plan.md)。

独立产品预览不连接 Harness，工作事实只能受控提供；正式插件的工作元数据由 WorkSources 进入。现有环境信号不包含按键正文、桌面截图、前台应用／窗口内容。本专项窗口探针只读取测试所需的窗口身份、几何和堆叠元数据；读取范围与验证见专项方案，窗口内容与标题不在范围内。

制作工作台、独立产品预览与正式 Host 分开使用。端口 4189 和本机 profile 的运行状态需现场核对；已有制作页可能包含未导出布局，复用前核对监听者，保留原页面。`.cache/`、`artifacts/`、`dist/` 只是本机或生成内容，不能作为接手入口或当前源码证明；启动和检查按[开发指南](development.md)进行，原生操作串行并使用隔离 profile。

## 继续产品实施时

用户要求继续产品实施时，按[跨平台方案](design/desktop-environment-plan.md)选择剩余工作。D0 尚缺 Windows／X11 的同场景结果、装饰窗口／跨应用及原生 Wayland 覆盖层验证；现有 `probe:desktop-environment` 的运行与结果语义见[开发指南](development.md#d0-真实桌面窗口探针)。缺少平台设备或实机结果时记录未验证，不用 macOS 代签。D1 首批正面、背面、右斜后已完成母版、25 个身体拆件与空手网格样片，见[资源表](design/d1-direction-assets.md)和[制作台](design/art-workflow/d1-directions-v1/README.md)；尚未绑定默认产品。剩余工作包括左侧不对称头饰、六方向连续转身、完整表情与产品接入；最小样片规格见[素材入口](design/aliveness-art-assets.md#d1-最小方向样片准备)。跨重启停靠和长期遮挡策略仍待设计与验证，具体可见要求见[空间与身体复核](design/space-body-review.md)；D2／D3 受 D0 能力门槛约束，第 6／7 期仍是后续候选。这些路线不自动扩展文档、清理或环境维护任务的执行范围。

桌面专项实施前的方案与入口见[规划快照](archive/2026-10-aliveness/desktop-environment-planning/README.md)。更早的开发状态、路线、素材入口与装配契约原字节见[空间与身体复核前快照](archive/2026-10-aliveness/space-body-review/README.md)。其他历史从[阶段归档](archive/2026-10-aliveness/README.md)进入；旧授权、旧下一步和进程状态只按形成时解释。
