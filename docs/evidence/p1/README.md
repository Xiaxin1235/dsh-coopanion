# P1 实施与验证记录

开始：2026-10-15（Asia/Shanghai）。功能范围见[陪伴契约](../../companionship-contract.md)及[路线图](../../roadmap.md)。这是新的实施记录，不修改 M1–M6 原始证据。

## 固定基线与预算

基线源码：`e2c7e39b97723f69fd77a209d93958a8e04aea30`，插件 0.4.9；开始时工作区仅有本轮路线图／素材计划文档差异，运行代码与该提交一致。宿主支持矩阵仍为 DSH 0.2.0-rc.2／0.2.1-alpha.1，实际执行版本在后续报告逐项记录。

在改产品代码前执行现有构建、类型／单元／收件箱 UI 检查以及隔离 profile 原生资源基线。原始报告新增到本目录；实际 Node、Electron、OS 和源码摘要由报告记录。

冻结目标预算：同机内置鲸鱼 180px，20 秒预热后各三段 60 秒，相对同轮 off 平均 CPU 增量 ≤单核 1 个百分点、平均进程树 RSS 增量 ≤32 MiB。两小时观察的最后半小时均值比预热后首半小时 RSS 增量 ≤20 MiB；这项和七天实际使用尚不能由短测试代替。若资源目标需调整，先新增说明与测量，不回写原始报告。

`baseline-idle.json` 是改产品代码前的源码构建观察：20 秒预热、3×60 秒、默认旧路径 off，平均 CPU 76.0016%（100% 为单核）、进程树 RSS 481.5416 MiB。报告记录实际源码／构建文件摘要。它没有固定随机种子；后续同轮开关组固定种子 17，所以不据此宣称跨版本性能改善或退化，也不将源码构建说成已安装的发布包。

### 资源失败与修正

S1 有界观察通过原预算，原始数据继续保留。随后 S2 三组独立进程采样的 CPU 超标：白天比 off 增加 3.676 个百分点，夜间增加 12.456 个百分点；RSS 均在 32 MiB 增量内，见 `final-resource-comparison-s2.json` 和 `final-{off,day,night}.json`。这次失败未删除，也没有提高原先冻结的门槛。

`paired-diagnostic-s2.json` 是同一进程、固定站姿、off／quiet 交替窗口的诊断，不能替代正式预算。新增父页面脚本约占单核 0.3 个百分点，主要消耗来自原有连续角色绘制和姿态差异。S3 仅在 P1 完全静候时将角色绘制限制为至多 30fps，累计真实 dt；工作、阅读、输入、悬停、动作及旧 off 路径继续原频率。配对诊断见 `paired-diagnostic-s3.json`，专项浏览器测试确认实际 dt 和占用时频率恢复。另修正了抚摸文字被悬停／自身开心反应过早收起的问题。

S3 正式资源观察直接从上述 `.tgz` 解包运行，复用已锁定的 Electron 依赖，使用新的隔离 profile。`cadence-{off,day,night}.json` 分别记录关闭、quiet 白天、quiet 夜间；均种子 17、20 秒预热、3×60 秒、真实时间。采样边界是原生 Electron 进程树，不包含 DSH 宿主或采样器，文件摘要须与 S3 对照。互动模式的半小时邀请、长期内存、物理锁屏和其他平台资源成本不由这三组短观察证明。
