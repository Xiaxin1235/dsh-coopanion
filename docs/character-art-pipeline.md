# GPT 辅助角色素材与建模计划

更新：2026-10-15（Asia/Shanghai）。这是[陪伴路线图](roadmap.md)的素材实施计划，当前尚未生成新图、制作新模型或更新上游运行时。现行包格式和导入规则仍以[角色接口](characters.md)为准。

## 依据与当前能力

用户指定的[上游鲸鱼 README（main）](https://github.com/Pal-AI-Lab/Coopanion/blob/main/packages/cortico-world-desktop-pet/examples/whale/README.md)说明了 ChatGPT 辅助制图、分件和网格驱动的方法；本次阅读时该文件最后修改提交为 `bd1743b96251f195b9d68cf70723c64281a03e17`，复核用[固定文件链接](https://github.com/Pal-AI-Lab/Coopanion/blob/bd1743b96251f195b9d68cf70723c64281a03e17/packages/cortico-world-desktop-pet/examples/whale/README.md)。

上游的制作要点是：先固定母版，再编辑补出遮挡区域，配准后分件，尽量保留母版可见区域的原像素；最终由贴图网格、变形器和共享身体驱动。这提供了制作思路，不能保证任意新角色一次出图即能绑定。下面的分阶段、质检阈值和样板范围是本项目的计划。

本仓库运行时固定在 `d7b1a0026fed3eb1975a6e0387527d806192cdbf`，见[导入记录](../web/upstream/UPSTREAM.md)。本地可复用的是 `kit.createRig()`、`kit.createBody()`、鲸鱼的分件模型与绘制代码、API 2 词表和 ZIP 导入。上游参考文件中的冬装、挂件等扩展不等于本地已有；本地鲸鱼当前仅有配色维度。当前也没有可直接执行的母版生图、ECC 配准和分件流水线，需另行制作。

这里的“建模”指 **2D 分件贴图 + 网格变形 + 枢轴／变形器绑定 + 动作参数**。GPT 负责母版和受约束的局部编辑；分层、遮挡补齐、坐标、网格、碰撞与动作仍需要工程处理和视觉复核。无需先切换到 3D 或另一个角色引擎。

## 与产品阶段相互衔接

| 素材阶段 | 建议交付 | 对应体验 | 完成门槛 |
|---|---|---|---|
| A1 小样板 | 一件纸星星玩具的透明母图与分件、近侧手臂持物姿势草案、静态叠放预览及素材清单 | 为邀请／一起活动准备视觉符号；验证新图能否与现有角色一致 | 身份／风格一致、透明边缘合格，明确需要新增的动作与图层；结果可判定继续或退回 |
| A2 可动角色包 | 一个独立 id 的 API 2 派生示例，接入纸星星，至少实现“展示 → 活动 → 收起”，并保留基础动作 | P2 的玩具和具象互动；之后再按同流程做零食 | 包可导入、动作可取消、真实输入与成长结算分离；浏览器、原生及重启回归通过 |
| A3 可复用内容流程 | 配色映射、服装／表情扩展规范、来源清单及生成／绑定模板 | P2／P3 的偏好、纪念物和季节内容 | 第二件素材能按模板制作，换装／缺词／资源测试通过，没有逐件修改宿主的要求 |

P1 的观察、自娱、休息和最小熟悉招呼使用现有动作；A1 不阻塞这些功能验收。A2 完成前，产品不得把泛用 `happy` 或 `dance` 文案包装成已经实现的拿玩具、吃东西。新服装先走独立包，不以整体升级上游作为前置条件。

## 制作流程

### 1. 先确定资产与动作的配合

每件素材先写清：使用场景、角色比例与朝向、持物的哪只手、站姿／坐姿、图层前后关系、绑定枢轴、互动范围和收起方式。P1 不改变这些资产；A1 从小道具验证，A2 才接入动态。

以纸星星为例，需要玩具本体、可握持的手部覆盖层和持物时的手臂姿态。它的大小、位置和显隐由角色绘制控制；UI 中“一起”活动的点击仍由可信宿主处理。仅靠把一张 PNG 放在角色旁边，不能获得手部遮挡、握持和动作收尾。

### 2. 建立母版与参考

新角色先生成一张完整、无遮挡、略侧身朝右的母版，保持适合当前 kit 的二头身和可镜像轮廓；固定画布、角色尺寸、落脚点、光源及线条。扩展现有鲸鱼优先编辑明确的参考图，锁定脸、发型、服装与比例，只改变本次指定区域。缺少原始母版时，先建立新的可追溯制作母版，不将现有拆分 PNG 当成上游原始生图证据。

GPT 图片生成／编辑优先使用当前可用的内置生图工具；透明资产请求真实 alpha。局部编辑使用明确目标图和参考图，只改变一个目标，逐次复核身份与姿势；不要靠独立生成几十张部件来碰运气对齐。生图在开发过程中执行，桌宠运行时无需模型凭据、网络调用或动态下载。若以后改用 API／CLI，模型、参数与成本另行确认，不在本方案绑定模型版本或价格。

提示词模板是制作说明，尚未执行：

```text
用途：桌宠的 2D 分件模型素材。
目标图：已固定的母版；其他图片仅作风格／形状参考。
本次修改：只补出近侧手臂被玩具遮挡的区域／只生成独立纸星星。
必须保持：角色身份、轮廓、画布、位置、比例、朝向、光源与未修改区域。
输出：单个清晰部件，背景真实透明，隐藏边缘有足够补画余量。
避免：额外物体、文字、水印、整图重构、姿势漂移、裁掉端点。
```

### 3. 分件、补画与配准

角色分件按身体结构拆分：后发、前发、脸、眉眼口、近／远侧手臂、躯干、裙子、腿、尾巴／鳍及道具。贴图需要画出旋转后可能露出的区域，手臂切口和头发遮挡处尤其要补齐。

采用母版编辑逐层移除／补画，结合差分或人工遮罩提取部件；对生成编辑图做 ECC 仿射配准及人工检查。纹理保持区域应尽量复用母版原像素；新增绘制仅进入目标遮罩，遮罩作为独立文件保留。配准失败、遮挡大或画风漂移时返工，不能继续依赖网格掩盖。

配准阈值需在 A1 固定源分辨率与保留区域后确定。记录保留区域的像素差异、关键点偏差和残差可视化；不能把上游个例报告的约一像素残差写成这条新流水线已经达到的指标。PNG 检查 alpha、孔洞、黑／白边及半透明污染，分别放在浅、深背景预览。

### 4. 坐姿与表情

坐姿下半身需要单独补画，再与站姿在同一身体坐标中对齐；手臂和裙子在切换中不能露出截断边。表情优先沿用现有结构：眼白／虹膜／睫毛分层配合程序眨眼、视线和嘴部脉冲，确实需要特殊轮廓时再增加替换贴图。新增状态必须在角色绘制中能读出变化，不能只添加一张无法被驱动的表情图。

食物和玩具分别处理贴近身体、手部覆盖、坐姿及镜像。新角色或新服装改变轮廓后重新评估几何、枢轴与命中区域，不能仅重着色后沿用全部旧坐标。

### 5. 网格、枢轴与程序驱动

按当前 256 逻辑空间建模：身体下方 `x=128`、脚底 `y=256`。母版像素到逻辑坐标的转换、部件 `box/grid/z/parent` 与 `pivots` 分开记录；头、腰、手臂、腿和道具各自有明确枢轴。

`createRig()` 接收网格部件与变形器；角色 `figure.draw()` 将共享 frame 的表情、视线、眨眼、说话、坐下程度和 `gesture` 映射成变形参数。头发、尾巴或道具的弹性只影响绘制，不自行接管物理移动。复用 `kit.createBody()` 的走动、重力和触摸事件。

新增动作先验证当前 kit 的自定义 `words` 能力：声明 `vocab`，使用 `opts.words` 定义 motion／expression，在 `figure.gestures` 与 `frame.gesture` 中绘制阶段变化；清单与 body 实际词表必须一致。持物／进食等动作是否需要更强的取消能力，在 A2 做小样后确定，不能凭一张新图声称 API 已支持全部过程。

角色动作表达“发生了什么”，宿主策略决定“何时发生”，成长模块决定“是否计入有效互动”。导入包的预览动作不会产生养成收益。新包通过传入的 `kit` 使用共享运行时；不能照抄内置鲸鱼对 `../kit/rig.js` 的路径并假设独立包也能跨目录加载。

### 6. 配色与服装

先固定单配色的几何和动作，再做受约束重着色，锁定轮廓与阴影结构。需要把母版配色应用到隐藏区域时，可建立原色到新色的映射并质检；不要让每次重生配色同时改变比例与五官。

服装会改变分件与遮挡：先制作同姿势服装母版，补站姿／坐姿，再实现角色自己的换装绘制。现有 manifest 支持 `axes/presets`，但本地鲸鱼绘制未具备参考 main 中完整的冬装实现；使用多轴并不自动实现对应视觉。几何重建的服装不承诺平滑渐变，配色渐变按实际渲染能力验证。

## 原始资料与可交付目录

拟议目录如下；本次未创建素材文件或流水线脚本：

```text
docs/assets/character-work/<asset-id>/
  README.md              # 来源、目标、提示词、工具／模型信息、校验值与处理记录
  originals/             # 母版与原始编辑图，保留原字节
  masks/                 # 编辑区域及分件遮罩
  derived/               # 配准图、透明分件与残差检查
  previews/              # 静态拼合及实际动作录制
examples/<new-pack-id>/
  figure.json
  figure.js
  model.json
  tex/                   # 包运行时实际引用的分件
  feat/
  README.md
  LICENSE
```

这是新增制作资料，不回写 `docs/evidence/` 的历史截图或素材。记录每次目标图、参考图、实际提示词、生成时间、实际可获得的工具／模型元数据、原文件 SHA-256、配准矩阵与处理参数；工具未返回的 seed／模型信息写“未提供”，不能补造。拟放入发行包的文件先核对体积，避免将全部制作中间文件无意随 `docs` 打包；大型原始文件需要确定可取回的保存位置与摘要，再保留轻量索引。

新增素材使用新路径和独立角色 id，不覆盖 `web/upstream/whale/` 的固定导入文件。派生代码与使用的贴图分别记录来源、许可和作者；沿用[第三方声明](../THIRD_PARTY_NOTICES.md)，原始声明保留原字节。生成辅助制作不会改变上游素材的权利归属。

## 视觉与工程验收

| 检查 | 通过标准 |
|---|---|
| 母版与透明分件 | 身份／线条一致；深浅背景下无明显脏边；遮挡后露出的区域已补画；静态拼合没有错位或孔洞 |
| 关节与极限姿态 | 左右镜像、抬手、低头、转脸、坐起、拖拽、抛掷落地逐项录制；无裂缝、露底、异常折叠或 NaN |
| 表情与口型 | 平静、开心、困倦、睡眠、工作／审批／异常及新增表情可区分；眨眼、视线和说话不破坏五官 |
| 道具动作 | 展示／活动／收起都有视觉结果；任务或用户手势打断后不残留道具；不能凭动作预览结算成长 |
| 多尺寸与输入 | 90／180／240px 以及两种朝向可辨认；新轮廓符合受限 box／hit，透明空白不吞桌面点击，气泡锚点合理 |
| API 2 包 | `figure.json`、实际词表、资源路径和回退一致；使用现有 ZIP 限制；重启、同 id 更新与切换配色保持正确 |
| 安全与资源 | 保留无网络的角色沙箱；没有自带模型凭据；记录文件量、纹理像素和同机 CPU／RSS，相对 A2 开始前的角色基线冻结预算 |
| 可追溯 | 原图、编辑记录、派生参数、预览和包摘要能对应；不能用静态叠图替代实际沙箱中的动画检查 |

使用现有 `npm run dev`／`npm run demo`、角色面板动作预览、`npm run character:pack -- <角色目录> <输出.zip>` 及 `test:ui`／`test:desktop`／`test:install` 扩展验收案例；新增动作涉及邀请或日常时还必须包含 `test:inbox-ui`。上游 README 的 `serve.mjs` 与装扮页面路由不属于本插件命令，不能直接套用。

A1 先证明素材可用，A2 再证明模型可动且可打断，A3 才证明流程可复用。图片质量、角色动作、成长逻辑和正式安装分别给出结果。
