## 最新体验结论与基础缺口

用户在本轮体验后明确指出：活动仍主要位于屏幕下方，拖高后仍会下落，人物只朝左／右，二维空间和面向用户的表现缺失，与 main 的可感知差异有限，尚无足够 LIVE 感。这是最新用户反馈，当前默认产品的空间与身体体验未通过验收；旧自动化和工作台验收保持其原范围。

源码核对确认：默认目标集中在底部窄带，拖放仍进入重力下落，身体朝向仍为左右镜像。完整问题、证据位置、影响和建议验收集中在[空间与身体复核](design/space-body-review.md)，后续接手必须先读该页。该页明确区分已实现能力与待实施目标。

## 验证与运行边界

浏览器使用真实 WebGL、导航、接触和存档，但输入与工作事实受控。隔离原生使用真实 IPC、OS 鼠标和系统键盘适配器；部分有界恢复测试控制输入枚举，不能替代物理键盘验收。四版本真实模型、物理多屏、三平台 CI、长期资源、日用安装和用户体验各自结算，固定报告不代表本轮重新测试。

当前 Linux CI 使用 Xvfb＋Openbox，只证明其 X11 场景；Wayland／Xwayland 的键盘输入当前为 unknown。Windows 原生键盘检查允许记录不可用状态，不能据其通过推断交互桌面输入已经可用。新增专项必须补齐正向能力与会话验收，不用本机 macOS 结果代替其他平台；具体门槛见[跨平台方案](design/desktop-environment-plan.md)。

独立产品预览不连接 Harness，工作事实只能受控提供；正式插件的工作元数据由 WorkSources 进入。现有环境信号不包含按键正文、桌面截图、前台应用／窗口内容。本专项窗口探针只读取测试所需的窗口身份、几何和堆叠元数据；读取范围与验证见专项方案，窗口内容与标题不在范围内。

制作工作台、独立产品预览与正式 Host 分开使用。端口 4189 和本机 profile 的运行状态需现场核对；已有制作页可能包含未导出布局，复用前核对监听者，保留原页面。`.cache/`、`artifacts/`、`dist/` 只是本机或生成内容，不能作为接手入口或当前源码证明；启动和检查按[开发指南](development.md)进行，原生操作串行并使用隔离 profile。
