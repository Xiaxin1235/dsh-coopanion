# 第 5B 期：有限相处记忆

当前范围与交付结果见[开发状态](../aliveness-development.md)。记忆复用默认产品现有的本地主页面、可信存档与显式互动闭环；第 5B 期自身未接通二维产品；后续[生活装配](living-integration-contract.md)将当前确认的有限类别用于整理前等待，保留已有招呼引用；自动生活仍不写相处经历。

## 可感知闭环

只接收主页面确认的真实抚摸，以及用户发起、明确回应并完整结束的一起活动。角色 iframe 的 touch、自动日常、任务完成、仅发起、取消及超时不能写成经历。手势、回应门槛和等待期限统一见[陪伴契约](../companionship-contract.md#有效互动与关系)。来源事件身份、原始类别、所有者时刻和写入修订随条目保存，角色 id 由外层分组绑定。

开心反馈可以即时出现，只有存档回执中包含本次唯一事件 id 才能声称已保存；一起活动保留原单次保存回执，抚摸按[5C 回应节奏](response-rhythm-contract.md)合并为至多一次稍后确认。全部写失败说明未能保存。反馈绑定角色／页面代次和反馈代次，被新互动替代或因工作／阅读／关闭陪伴收起后，不由迟到回执重显。记忆与关系成长分别结算：成长冷却中的真实互动也可留下记忆，但不增加计分或邀请预算。

下一次用户主动开始一起活动时，等待气泡按最近有效条目的原始／纠正后类型提到上次一起玩或摸摸；没有记录就用初次招呼，不凭分数编造经历。最近有效的“一起活动”还可让下一次已获准的低频邀请在挥手后增加既有点头；熟悉招呼的爱心仍按原解锁规则保留，缺词安全回退。记忆不新建邀请或模型调用；抚摸回应的运行期合批队列由[5C 契约](response-rhythm-contract.md)单独维护，不改变本页存档准入。

## 查看、纠正与删除

右键菜单 → **相处记忆** 显示当前角色的确认条目，可纠正为抚摸／一起活动、删除单条或清空。纠正保留原始类型和来源，另存确认类型；展示与后续招呼按纠正值派生。关闭陪伴后仍能管理已有记忆，打开记忆属于用户占用，当前未完成活动会被打断且不记成功。

只显示存档所有者确认的摘要；写失败不新增条目，冲突刷新修订且不重放互动。换角色立即清空旧视图，异步回执绑定原角色和页面代次。无自由文本、人物画像、聊天／工作正文或模型总结。全 profile 的显式设置不复制成推断画像。

## 容量、迁移与删除

`CompanionStore` 使用 schema 2，原数据目录名称保持 `companionship-v1`。schema 1 读取时仅在内存迁移，保留关系、预算、quiet、幂等身份及修订，不把已有关系分数编成历史记忆；下一次成功变更才原子写成 schema 2。损坏、未来 schema、锁冲突和写失败沿现有降级规则处理，保留原字节。

每角色最多 16 条，全 profile 最多 128 条，超过时按写入修订淘汰最旧条目；保留期 30 天，读取隐藏过期条目，下一次成功变更清理。关系记录与记忆／撤销记录分别最多覆盖 256 个角色，整个存档最多 256 KiB。撤销代次不因容量淘汰而回收；达到角色上限拒绝新增，不能通过回收撤销标记让旧事件恢复资格。

事件在发生／活动发起时捕获当前记忆代次，一起活动到真实完成后才提交。纠正、删除、清空及卸载角色会轮换并持久保存该角色的撤销代次；此前捕获的事件即使携带最新修订，或已退出最近 128 个幂等身份窗口，也不能再写入记忆。新真实互动从新代次开始。删除详情不会撤销已结算的关系分数；卸载角色仍删除关系，但保留空的撤销标记。没有另存记忆摘要／缓存可以重建已删条目。

单写、串行、修订检查及临时文件原子替换继续由同一存档所有者负责。老客户端未携带记忆代次时只走原关系接口，不创建记忆。主 frame IPC／同源 HTTP 均沿现有来源和已安装角色检查；角色包无存档权限。

## 验证入口

- `tests/companion-memory.test.ts`：容量、独立计分、重复、迁移、纠正／删除、跨重启撤销、写失败／冲突／多实例和损坏／未来 schema。
- `tests/companion-client.test.js`：角色代次、排队前捕获记忆代次和活动原代次。
- `tests/companion-http.test.ts`：同源、角色存在与有限纠正类型。
- `tests/companionship.test.js`：招呼变化、缺词及 quiet 边界。
- 完整 `npm run test:inbox-ui` 包含真实活动完成、重载查看／纠正／删除、原有草稿／阅读／输入身份及抚摸准入回归。
- `COMPANION_EVIDENCE_DIR=<新目录> node tests/companionship-native.mjs` 使用临时 profile 检查 Electron IPC、真实活动、跨重启、纠正和删除，与其他原生操作串行。

浏览器、隔离原生、真实物理设备、三平台 CI 和主观观感分别结算；固定交付与发布状态从开发入口及对应报告核对。
