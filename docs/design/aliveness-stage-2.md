# 第 2 期：真实二维运动与单屏桌面验证

这是当前下一项实施范围，状态与基线以[开发入口](../aliveness-development.md)为准。目标是在现有潮汐小院中点选目标后，由身体实际沿合法 x/y 路径移动、绕障、转向和停稳，并在隔离原生单屏中验证坐标、命中和回执。编辑摆放与水平拿放是已有基础。

## 1. 先校准空间含义与反馈

用户将花箱放到左上角 `(508,261)`，视觉上有空隙，当前界面仍显示“不可通过”。复现依据为第 1 期 `geometry.js`：花箱矩形 `112×105`，底缘 `366`；固定路线点 `(450,555)` 的身体加余量包络为 `x=338..562, y=338..575`，与花箱交叠 `54×28px`。无 12px 余量时仍交叠 `42×16px`。路线不会随编辑后的角色位置移动，当前检查没有搜索替代路线。

这说明保守矩形与固定折线冲突，不能证明实际轮廓无法通过或整个地图无路可走。先将以下含义写入模型、界面及测试，再接运动：

- 区分美术矩形／透明留边、身体运动碰撞体、地面实体、交互范围和遮挡深度。按实际姿态和运动方式标定；阴影或合理前后遮挡不自动成为实体碰撞。
- 手动内容禁区继续约束完整身体及持物范围；真实实体的阻挡也应覆盖实际运动扫过的形状与必要余量。不能为使示例通过而统一缩成脚点。
- 判定反馈指出冲突对象、路线段和采用的包络；区分“当前路线冲突”“找到替代路线”“在当前模型与搜索范围内不可达”。标明规划精度和保守边界。
- 为上述花箱位置、紧邻边界、门柱间隙、透明留边、前后遮挡与禁区分别建立能识别错误语义的回归；该位置不预设必须变绿，以校准后的模型和真实路径为准。

## 2. 形成真实身体与运动接口

先核对现有 body、角色沙箱、宿主协议与窗口坐标；确定最小可维护接口，再实现 body 内 x/y、速度、朝向、起停和转向。绘制、脚／手／物件锚点、命中区域、阴影与气泡共用实际位置。旧 API 2 水平 `walk(x, run, id)` 保持兼容，通过明确能力协商启用二维角色；修改固定上游时同步来源和补丁说明。

路径执行检查完整扫过范围，结合转向与制动余量；换目标从当前连续状态重规划。实际位置与停稳满足条件才产生 arrived；取消、拖动、生命周期挂起、对象失效或几何修订产生对应中断，旧角色代次／操作身份／路线修订的回执不得推进新目标。计时只用于节奏与超时，外层 CSS 平移、编辑 `place` 或预定计时不算二维执行。

先完成最小 x/y 移动和坐标映射后，就用隔离 profile 验证真实 Electron 单屏，再迭代绕障与动态变化。复用已存在的原生测试入口与安全开关，系统桌面操作串行；保持用户日常安装与设置。

## 3. 在同一地图完成可操作闭环

保留现有角色、SVG 场景、O03 连续手部及同帧 `palm < shell < fingers` 合成。用点选目标和运行时障碍变化展示真实路径，至少覆盖：

| 场景 | 可观察结果 |
|---|---|
| 普通目标与两轴移动 | 真实 x/y、自然停转、到达一次、绘制／命中／气泡一致 |
| 直路被花箱挡住但有绕路 | 规划并实际执行合法替代路线，反馈解释所用碰撞体 |
| 目标或全部通道被阻挡 | 说明当前模型下的原因；身体停在合法位置，无假到达 |
| 移动中改变障碍、目标或几何 | 安全制动／重规划或中断；连续位置，旧回执不串入新目标 |
| 真实指针拖动与取消 | 旧路线失效，松开后按新位置处理；无回弹或迟到回执 |
| 重复换目标、暂停与长间隔恢复 | 操作身份明确，恢复时不越界、不吞首次继续 |
| 返回已有拿放故事 | 稳定接触及实际开合才交接物件；两轮反向、暂停／逐帧和同帧遮挡仍成立 |

本期不要求全部坐卧／独立肘膝或任意姿态接触；具体关节缺口在真实运动画面中定位并记录，必要时补最小素材，不重做整套角色。

## 4. 完成条件与证据

1. 几何／规划／连续运动／取消与旧回执有针对性回归，包括本次花箱反馈；实际浏览器指针交互和障碍变化证明临场响应。
2. 按改动完成类型检查、构建、单元与完整 `test:inbox-ui`，保留原 O03 像素、44 项动作及长暂停回归。新增测试应能在对应错误实现上失败。
3. 隔离原生单屏覆盖两轴移动、坐标／点击穿透与命中、气泡位置、拖动取消、挂起恢复和旧水平角色回退。受控原生、CI 矩阵和物理多屏分别报告，未运行的范围明确列出。
4. 交付可操作的同地图预览、30–90 秒真实录像及一次改变条件的演示；画面连续性与用户观感单独结算。
5. 实现同步更新空间草案、角色接口、使用说明和当前状态；新证据绑定实际提交、宿主／浏览器版本及包或源码摘要，旧记录原字节保留。完成本期本地提交后报告结果。

## 范围边界

本期实现运动能力与单屏桌面验证。生活／工作保留独立意图，未来经唯一身体拥有权入口执行；完整协调、工作交接剧情、生活调度、人格、出门、自动读取工作区和跨屏属于后续阶段。工作完成继续由 `src/completion.ts` 判断，会话接受回执另行结算。

继续遵守 companionship 默认 off、roam 许可、输入 unknown 安静降级、固定用户尺寸、减少动态替代和现有单一 tick／帧率约束；不读取其他应用内容或引入模型日常调用。开发限 `codex/aliveness-foundation`，不合并、不推送、不发布。
