# 连续动作与物件：第 3 期预览契约

状态：2026-10-20 用户授权开始第 3 期，实现在 `codex/aliveness-foundation` 的显式制作预览。工程验证与用户观感分别结算，当前结果看[开发状态](../aliveness-development.md)。本契约覆盖同地图、180px 主配色鲸鱼与 40px O03；默认产品工厂与生活／工作调度尚未接入。

## 入口与身体拥有权

[第三阶段页面](http://127.0.0.1:4189/docs/design/art-workflow/space-v1/index.html?stage=3)显式提供 `bounds.continuousActions=true`。旧页面继续使用第 2 期地面模型及水平拿放；它的既有验收独立保留。

`kit/space-action.js` 是本地纯执行器，复用 `prop-motion.js` 的姿态采样及 O03 接触提交。只有该执行器能在一次拿放中发出导航、转身与接触操作。普通点地导航只在动作待机时接受；动作拥有身体期间不并行另一条路线。预览每帧仍只有原来的一个 tick，不接模型、工作事实、关系存档或第二个生活调度。

## 空间与接触

角色、地面贝壳和落点各有独立 x/y；贝壳 y 指实际地面四边形底缘，抓握点由同一规格换算。接近目标按既有肩／腰变换计算站位，body 内导航从实际根移动到该站位和物件地面高度。拿放无需回到初始水平平面；仍只支持已标定的平地 O03 接触姿态，不声明任意高度、任意物件或任意角色抓握。

持物导航沿用实际根与同一手部变形链，并与手动导航共用[空间契约](living-space-contract.md)的标定模型：实体地面占用按完整宽度的 `200×32px` 身体地面包络绕行；内容禁区、世界边界及未标定实体按完整 `200×213px` 身体／持物包络避让，均增加 `12px` 余量。指定规格的手部和持物仍通过实际解码画面及持物四边形核对完整包络，不能把屏幕中的立面高度重新当成地面纵深。立面参与前后遮挡，不制造额外地面墙。

首次第 3 期曾将所有立面改成完整禁区，导致用户反馈的花箱 `(580,528)` 与岗位形成虚拟墙；花箱移到 `(558,252)` 后，小窝立面仍错误封住贝壳接近站位。2026-10-20 反馈修正恢复统一地面模型，并覆盖真实到岗、拾取、持物放下和安全边界。首轮固定验证仍只解释当时的源码。

远离身体的地面贝壳有自己的纵深单元；进入同一接触平面及范围后回到同帧合成。身体／掌部、贝壳、前景指尖保持既有顺序，拥有权改变不重建素材。身体、气泡、命中和持物都来自同一实际根。

## 进入、操作与退出

| 阶段 | 完成条件 |
|---|---|
| 清醒坐姿 → 起身 | 显式 `stand`，从当前姿态连续准备；至少 0.8 秒准备且真实 sit 权重 <0.01、身体不移动才发导航；6 秒未站稳则暂停 |
| 接近／持物导航 | 回执 id、角色代次和几何修订匹配，实际根距离目标 ≤0.5px，实际速度归零；30 秒没有有效到达则暂停 |
| 站稳／转身 | 沿用实际朝向与手臂角，等身体停止且实际朝向到位，再进入伸手／放低 |
| 拿起 | 真实手／壳缘距离 ≤1.5px，连续至少四个稳定采样，达到接触姿态和握持闭合门槛后提交一次 |
| 放下 | 真实物件地面锚点与落点纵深、抓握点横坐标误差合成 ≤1.5px，稳定采样及张手门槛满足后提交一次 |
| 收手／起身退出 | 延续当前姿态及已提交拥有权，结束后待机；未提交操作不因耗时而变为成功 |

准备与动画时长只定义衔接节奏，不能代替站稳、导航回执、实际接触或手部开合。拿起前 `owner=ground`，提交后 `owner=hand`；放下提交才回到地面。旧 O03 的超时和接触失败路径继续有效。

## 中断与恢复

暂停保存动作相位、当前姿态、实际位置、手部开合、目标和已提交计数；不调用 figure reset。恢复导航使用新的单调 id，重新检查当前身体、物件与几何。旧 id、旧代次或旧几何的回执都不能推进动作。

手动路线与动作路线保留各自对外身份，适配器经一个有界、单调的物理导航通道执行并映射回执；只保留最近 64 个映射，过期映射直接丢弃。连续拿放完成后继续点地行走，不会因身份计数互相覆盖而失效。反向拿起在手部局部反射物件，保持抓握点与原地面纹理朝向；移动中再随身体连续转向。

接触前后、半转身、坐姿起身、移动中均可暂停。恢复局部拿放或退出时不重播已提交的拿起／放下；几何变化发生在放下之后，也只续接收手／起身。生命周期长间隙、页面隐藏、受控原生 suspend 和 Escape 都保守暂停；恢复待机不会自动发起拿起。

直接拖动角色先暂停动作，按同一实体地面／完整禁区模型检查实际拖动段，松手或取消保留最后合法根和物件拥有权。拖动后继续从新位置重新评估原目标，不瞬移回原平面。数值试摆、恢复样板和“复位动作”是显式重置，推进角色代次并清空本轮计数；独立贝壳位置保留至用户明确重摆或恢复样板。

地面贝壳只在待机／清醒坐姿时编辑，手中物件不能外部脱离。落点或实体变化修订世界并暂停旧操作，继续后再规划；与当前实体地面／完整禁区包络冲突的摆放拒绝。导航拒绝时保留 `target-blocked` 等具体原因，界面说明接近站位受阻，不能只显示笼统的 `interrupted`。实体／落点编辑可作为现场改变条件的验收输入。

## 验证与范围

`tests/space-action.test.js` 检查状态、旧身份、错误到达、能力缺失、无效坐标、生命周期、提交及修订恢复。`tests/space-action-ui.mjs` 同时支持 Chromium 和 `--native` 隔离 Electron；真实绘制、body 导航、指针拖动及接触判断均保留。`tests/space-action-showcase.mjs` 录制一个现场改落点、持物暂停和完成拿放的页面故事。

证据包含 base commit、实际源文件 SHA-256、Node／Chromium／Electron 版本、检查结果与截图／录像。它们不代表用户观感验收、三平台矩阵、真实 OS 休眠／锁屏、物理多屏或长期稳定性；不产生安装／发布结论。旧空间、O03 像素／44 项动作、角色 UI 与完整 `test:inbox-ui` 分别回归。
