# 生活感实施路线

本页维护演进顺序与架构取舍。当前执行范围只看[开发状态](../aliveness-development.md)，具体行为以相应契约为准；早期完整蓝图保存在[5B 阶段归档](../archive/2026-10-aliveness/stage-5b/README.md)，本次调整前路线见[复核前快照](../archive/2026-10-aliveness/space-body-review/README.md)。

## 1. 演进顺序

空间与美术基础 → 二维运动 → 连续动作与物件 → 生活／工作协调 → 人格、记忆与回应节奏 → 出门与关系痕迹 → 跨屏。每期交付可操作的可见闭环，不只播放动作或扩充台词。新美术由实际画面缺口驱动，见[资源入口](aliveness-art-assets.md)。

2026-10-22 默认产品体验发现空间与身体基础仍有缺口：目标集中底部、拖放仍下落、只有左右身体朝向。后续按[跨平台桌面互动方案](desktop-environment-plan.md)在现有路线中增加专项，先核对平台能力并补齐[平面位置与多方向身体](space-body-review.md)，再交付真实窗口互动。阶段编号描述已有工作结构，不表示默认产品按编号全部验收完成；专项已进入实施路线，进度与验收见开发入口。

| 阶段 | 契约或规划边界 |
|---|---|
| 1–2 空间与二维运动 | [生活空间](living-space-contract.md)：工作台的地面、立面、完整禁区、导航和真实到达；默认产品的平面拖放／多方向身体尚有上述缺口 |
| 3 连续动作与物件 | [连续动作](continuous-action-contract.md)：接触提交、持有、放下和中断恢复 |
| 4 生活／工作双线 | [双线协调](life-work-contract.md)：独立意图、唯一身体拥有权和真实工作事实适配 |
| 5A 人格影响行为 | [人格行为](personality-behavior-contract.md)：稳定偏好与当下情绪分开，不扩张工作或邀请权限 |
| 5B 有限相处记忆 | [记忆](companion-memory-contract.md)：可信事实、有限存档、查看／纠正／删除、可感知回应 |
| 5C 回应与安静节奏 | [回应契约](response-rhythm-contract.md)：即时反应、同类合批、有界候选与占用优先；默认产品已实现该模块 |
| 当前基础补强专项 | [跨平台桌面互动方案](desktop-environment-plan.md)：D0 平台探针 → D1 默认空间与身体 → D2 共享环境／几何 → D3 三平台窗口切片 → D4 节奏与交付；实际进度见开发入口，复用第 1–5C 期 |
| 6 出门与关系痕迹 | 后续候选；缺席、留言与归来须先定身份、期限和实际完成证明，不编造离线活动 |
| 7 跨屏 | 后续候选；须处理真实 workArea、混合 DPI、拖放和生命周期，不把单屏制作预览当成跨屏产品 |

## 2. 架构与装配边界

生活线保留对象、目标、步骤与进度；工作线消费可信 Harness 事实；协调模块决定身体、物件、视线、表情与社交通道的拥有权。两条意图线可保留状态，但不能同时发出身体位移。

默认产品已通过[生活装配](living-integration-contract.md)将导航、连续物件、生活／工作和人格接到主页面，复用可信互动存档与回应节奏；当前目标仍在底部窄带，拖放保留重力，身体仍为左右朝向。装配完成不等于默认产品二维生活空间已成立。第 4／5A 期工作台继续提供独立编辑和模拟事实；正式 Host 快照由同一 WorkSources 所有者提供有限元数据。工程通过与用户 LIVE 感分别结算，模型调用、自改人格和额外角色人格均不属于隐含依赖。

## 3. 连续执行与真实状态

到达、接触和完成由实际几何／匹配回执证明，耗时只用于节奏。打断从实际姿态安全退出，保持物件拥有权；恢复时核对原目标和当前事实，不重播已提交动作。支持的小景使用共享二维身体工厂与唯一协调器；简单 NPC 回退与小景互斥拥有身体，关闭小景时先完成安全交接。

## 4. 验证与交付

实现、测试、使用说明、契约和本地提交一起交付。浏览器、受控 Host、隔离原生、系统实机、三平台 CI、正式安装／发布和用户观感分别结算。固定数字与失败过程进入[报告](../reports/README.md)，历史阶段进入[归档](../archive/2026-10-aliveness/README.md)。

## 5. 跨平台桌面互动专项

采用共享空间／行为 Module 与可替换平台 Adapter，不另建原生桌宠或第二身体引擎。窗口信息只提供互动候选；基础生活不依赖其他应用窗口，工作完成与存档继续由既有所有者判断。详细 Interface、放置／附着规则、工作包及停止条件统一维护在[专项方案](desktop-environment-plan.md)。

Windows、macOS、Linux X11 使用同一场景验收；现有 Linux CI 的 Xvfb＋Openbox 结果不外推到原生 Wayland。Wayland 的全局定位、输入和窗口能力必须单列探针及产品承诺，不用静默回退冒充功能对等，也不自动缩减现有 Linux 支持声明。本页维护采用路线；实施授权与交付状态只在开发入口维护。
