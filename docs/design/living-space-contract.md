# 生活空间契约草案：第 1 期

状态：仅约束 `codex/aliveness-foundation` 的 [space-v1 制作预览](art-workflow/space-v1/README.md)。已发布行为仍按[自主陪伴契约](../companionship-contract.md)解释。下一项按[第 2 期范围](aliveness-stage-2.md)接入实际二维身体，再扩展运动、回执与能力协商。本草案记录第 1 期已实现模型，保守矩形并非后续实体碰撞体的最终定义。

## 坐标与身体

世界为 1080×660 逻辑 CSS px，原点左上，x 向右、y 向下。屏幕不足时等比缩放整个编辑画板；指针坐标除以同一缩放因子。尺寸 180px 指现有 API 2 的 256 单位参考身体缩至 180px，并非角色所有透明边缘的实际高度。相机缩放不改变世界规格。

身体根为双脚中点 `(bodyX, floorY)`，无透视缩小。分层身体、脚、手掌、壳缘和物件四边形取同一真实绘制帧；不另推测接触点。保守包络相对根为 `[-100,-205]..[100,8]`，连接路线四周另预留 12px。该余量是几何预留，不等同于已验证的运动转弯半径。

实际 WebGL 栅格解码后在世界坐标测量 alpha>8 的身体／手部范围，并计入持物四边形。包含编辑摆放和两轮左右拿放的实测范围与包络分别记录在浏览器报告；这些样本不能推广到未验证的任意姿态、角色、尺寸或朝向。

生活锚点 `(240,555)` 与岗位锚点之间的样例折线依次为 `(450,555) → (540,575) → (700,600) → (850,600)`，总长约 614px。它固定在场景中，编辑角色不会把路线首点自动改成当前根。编辑岗位实体也不自动移动岗位到达锚点；出现冲突应修改几何后重新验证。

所有实体矩形是包括图案、透明留边和阴影在内的保守阻挡区。碰撞检查将矩形按身体左右、上沿、下沿与余量作 Minkowski 扩张，逐条线段做连续区间求交；接触边界也判冲突。世界边界同样检查整个包络。实体隐藏或区域叠加层关闭不改变碰撞含义。

当前“不可通过”只表示这条固定折线与上述保守包络冲突；未搜索替代路径，也未区分图案透明留边、地面占用与可接受的前后遮挡。用户花箱 `(508,261)` 的复现及碰撞语义校准列入第 2 期；不能由现有反馈推断整个空间不可达。

## 编辑、水平拿放与遮挡

编辑态支持拖动或数值摆放。角色拖动在松开时一次性提交，点击选择不重置；实体／贝壳拖动实时更新。编辑角色／平面明确复位拿放状态；它使用 API 2 `place` 和平面设置，不是二维导航，也不产生 arrived 或任务完成回执。编辑只保留在当前页面，导出供下一阶段使用，刷新恢复样板。

真实拿放继续使用现有 `createMotionBody`、`prop-motion.js`、连续手部网格和同帧合成；只有接触稳定且实际闭合／张开达到门槛才提交。当前动作在一个水平平面执行；沿途保守包络若与实体相交，禁用开始／续接拿放。动作中锁定编辑，可暂停、继续和逐帧检查；行走暂停期间不启用单帧步进。

场景实体按底缘 y 排序，身体／掌部、贝壳、指尖作为一个完整绘制单元参加同一深度排序；单元内始终按 `palm < shell < fingers`。两张身体／指尖图像都解码后才一次性曝光完整帧，拥有权交接只改变物件绑定，不换独立外层物件。

## 后续接口边界

第 1 期只形成几何与美术规格。没有真实 x/y 路径执行、动态重规划、身体协调或自动工作区来源；没有原生窗口／安装／跨屏验证。现有产品 API 2 仍为水平 `walk(x, run, id)`，不为本预览新增公共二维 API。

生活线与工作线保留各自意图，未来统一经过唯一身体拥有权入口。两条线当前只在空间中标出语义，不加载两套调度器，不解析 Harness 正文或另造完成语义。后续工作事实继续复用 `src/completion.ts`，接受回执与完成分别结算。
