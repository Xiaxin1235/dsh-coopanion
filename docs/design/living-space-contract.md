# 生活空间契约：单屏制作预览

状态：约束 `codex/aliveness-foundation` 的[潮汐小院](art-workflow/space-v1/README.md)及隔离 Electron 单屏预览，第 2–4 期共用本页坐标与几何模型。第 3 期连续物件规则见[连续动作契约](continuous-action-contract.md)，验收与下一阶段授权见[开发状态](../aliveness-development.md)。默认产品仍按[自主陪伴契约](../companionship-contract.md)运行；第 4 期[双线预览](life-work-contract.md)消费明确标注的模拟事实；正式宿主事实适配已单独验证，默认产品二维装配与跨屏尚未实现。

## 坐标、身体和绘制

世界为 1080×660 逻辑 CSS px，原点左上，x 向右、y 向下。窄窗口等比缩放整个画板，指针与原生窗口 DIP 经同一画板矩形换算。180px 指 API 2 的 256 单位参考身体缩至 180px，不含相机缩放；身体不随深度缩小。

实际根为 `(bodyX, bodyY)` 双脚中点，由 body 内的导航器推进。完整保守身体为 `[-100,-205]..[100,8]`，规划四周增加 12px。它用于世界边界、内容禁区及未标定实体，覆盖指定规格的站立、行走、O03 手部及第 3 期持物导航，不推广到任意角色／姿态。WebGL 解码后的 alpha>8 与持物四边形仍实测留档。

绘制矩阵、脚／手／物件投影、命中圆、气泡和阴影都来自这一实际根。进入接触范围后，主体／掌部、贝壳、指尖解码完成后一次性合成；内部始终 `palm < shell < fingers`。场景按标定地面占用的底缘 y 排序，未标定对象回退到美术底缘；完整合成单元以实际根 y 参与深度排序；第 3 期远离身体的地面贝壳独立按自身纵深排序。前后遮挡、地面装饰和阴影不自动变成实体。

## 几何的不同含义

`space-v1/geometry.js` 保留第 1 期 `checkRoute` 作为历史对照，真实运动使用 `navigationModel`：

| 含义 | 本期处理 |
|---|---|
| 美术矩形 | 包含透明留边、阴影的完整资源摆放尺寸；用于编辑与深度 |
| 实体立面 | 保留枝叶、桌面、屋顶、柱体的可见范围与深度遮挡；在不同纵深可合理重叠 |
| 实体地面占用 | 已标定素材的底座／盆体／桌脚／柱脚范围，参与地面绕行；阴影不算占地 |
| 身体地面占用 | 横向 `[-100,100]`、纵深 `[-24,8]`，即 200×32px，加 12px 余量；完整宽度和有限纵深连续扫过 |
| 完整身体限制 | 内容禁区、世界边界及未标定实体仍按完整 200×213px 加 12px 检查 |
| 手动内容禁区 | 整个矩形与完整身体避让；不读取其他应用 |
| 交互范围 | 选中／拖动命中和 O03 真实接触范围，均不作为可行走证明 |
| 遮挡深度 | 决定绘制先后，不改变碰撞；隐藏区域图层也不移除实体 |

初始对象仍为小窝 `65/155/210/175`、岗位 `820/245/170/120`、花箱 `485/220/112/105`、北柱 `621/280/28/40`、南柱 `621/622/28/32`、禁区 `755/40/280/195`。实体相对美术矩形的标定分别为：小窝 `18/2/176/164`（210×175 源图）、岗位 `7/6/156/109`（170×120）、花箱 `6/6/101/91`（112×105）、柱 `3/2/22/34`（28×40）。尺寸变化按源图比例映射；小窝开口不声明可进入。

标定实体的地面范围分别为：小窝 `18/145/176/21`（210×175 源图）、岗位 `7/81/156/34`（170×120）、花箱 `6/60/101/37`（112×105）、柱 `3/22/22/14`（28×40）。它们按素材比例缩放，立面与地面范围一起导出。这里采用具有纵深的画面空间约定；角色的屏幕高度不能直接当成地面纵深。未标定对象保留完整身体碰撞，不自动套用地面规则。第 3 期持物二维移动使用同一模型，完整手部／持物另核对实际包络；任意姿态占地仍未声明。

界面区分直达、替代路线与当前模型下不可达，列出直线冲突的对象、段号和包络；某条固定路线冲突不等于全地图无路。两轮花箱反馈及全立面模型错误封路的过程，分别保留在[第 2 期归档](../archive/2026-10-aliveness/stage-2/README.md)和[第 3 期归档](../archive/2026-10-aliveness/stage-3/README.md)。

## 规划、连续执行与回执

`web/upstream/kit/navigation.js` 按对象种类通过 Minkowski 扩张将有限身体占地或完整身体化为根路径，连续线段求交，接触障碍边界也算冲突。可见图搜索扩张矩形角点，角点外留 0.5px；这是有精度边界的保守矩形搜索，不能证明任意真实轮廓不可达。世界边界同样包含整个包络。

实际身体速度上限 100px/s、加／减速 180px/s²；逐帧预算当前位移后的制动距离，不跨越拐角。到拐角停稳后转向再起步，最终根到达、速度归零且稳定 0.4 秒才发出一次 `navigation-arrived`。计时只用于转向／稳定节奏，不代替位置证明。所有执行段再次连续检查，不能穿过薄障碍。

手动导航换目标沿旧合法段制动，再从实际制动终点重规划。修改实体即增加几何修订，手动导航重规划；第 3 期连续动作先暂停，显式继续后再核对与规划。当前身体重叠的新摆放在运动期间拒绝，前方突然阻挡则安全中断。无法到达的目标不会产生 arrived。取消、Escape、拖动、生命周期／长帧间隙、身体动作抢占、几何变化分别中断。拖动通过真实指针连续更新 body 内根，按相同地面／完整禁区模型检查连续扫过段，松手／取消停在最后合法位置且不回弹；第 2 期建立新水平操作平面，第 3 期保留物件拥有权并按连续动作契约续接。

操作身份同时包含单调 id、角色／操作代次 generation 与几何 revision。导航器拒绝旧 id、旧代次及同代次旧几何；页面只结算当前三元组，旧 iframe 消息还由 frame source 隔离。暂停保留目标，继续用新身份从实际位置规划；长暂停后的首次继续可执行。只有显式重新初始化才允许新代次采用低修订号。

## 旧角色、拿放与原生边界

二维能力必须由 body 的 `capabilities:['navigation-2d-v1']` 握手，并且工厂显式 `kit.createBody(host,{figure,navigation:true})`。默认角色与旧 API 2 `walk(x,run,id)`／`arrived` 保持水平行为；无能力时 `body.navigate` 返回 false，不伪造二维移动。协议详见[角色接口](../characters.md)。

无参数的第 2 期页面与独立 O03 工作台仍在明确的水平操作平面拿放；导航期间／离开平面禁用原拿放，可用“复位动作”返回故事。第 3 期 `?stage=3` 从当前位置二维接近独立物件与落点，持物导航和拖动后续接遵循[连续动作契约](continuous-action-contract.md)。两个模式均由实际接触与开合提交拥有权，旧像素、反向拿放、暂停／逐帧及动作回归继续保留。

`node scripts/space-desktop.mjs` 使用临时隔离 profile 打开同地图真实 Electron 窗口。默认地图可操作，“桌面穿透”开启后以实际 body 命中圆恢复输入，空白区域调用原生 ignore-mouse；Escape 关闭穿透，取消手动目标或暂停连续动作。生命周期从 powerMonitor 转发。该入口不读取其他应用，不加载日用安装，不连接 Harness，也不代表主产品自主生活已接通。

本期原生验证覆盖单屏受控窗口、实际 macOS 光标映射／穿透切换、拖动和受控挂起；操作系统实际休眠／锁屏、底层应用点击送达、跨屏／混合 DPI、CI 三平台矩阵均独立结算。验证身份和录像见[当前状态](../aliveness-development.md)。
