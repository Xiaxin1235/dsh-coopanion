# 默认产品空间与身体：问题复核及下一步建议

状态：2026-10-22 用户体验反馈与源码复核。基线为 `2737a3ebae40bd1028628aa5cf4e602a362ecb0d`；本页记录已知问题和待实施建议，本页是缺口与验收依据，实施进度统一看开发状态。当前任务见[开发状态](../aliveness-development.md)，现有行为见[生活装配契约](living-integration-contract.md)。

## 体验反馈与实现证据

用户指出默认体验仍局限于屏幕下方，拖起人物会坠落，人物始终朝左或右、没有朝向用户，与 main 的体验差异有限。此前还指出探索链条机械、重复弯腰空抓、动作卡顿、家具遮挡及环境互动缺少因果。`2737a3e` 对前一轮问题做了工程修正，固定测量见[报告](../reports/desktop-feedback-20261022.md)；最新反馈表明空间与身体体验仍不足。没有本次 main／分支同场景对照录像，不把主观比较改写成量化测量。

| 问题 | `2737a3e` 基线源码依据 | 对体验的影响 |
|---|---|---|
| S1 默认目标集中于底部 | `web/living-space.js` 用 `height - 24` 定义 floor；贝壳、边界观察与停靠目标均邻近该高度，配置主要提供横向 home／range | 寻路可处理 x／y，默认目标却没有形成跨区域二维活动 |
| S2 拖放仍有重力语义 | `web/upstream/kit/body.js` 的 `dropAt` 将 drag 切为 air，沿既有物理系统落向 floorY；主产品拖放沿用 API 2 drop | 用户放到上方的位置无法成为稳定生活位置；导航根 y、物理高度和拖放平面尚未统一 |
| S3 身体朝向仍为左右 | 同一 body 的 facing 为 ±1，经 faceVis 镜像绘制；该基线缺少正面／背面／斜向完整身体表现 | 纵向位移仍像侧身平移；视线移动不能替代正面面向用户 |
| S4 已接通的模块缺少共同空间表现 | `living-routine.js`、`life-work.js` 与 `living-body.js` 共享目标和身体，但消费 S1 的底部目标与 S2／S3 的身体语义 | 记忆、人格和工作交接已有作用，整体仍易被感知为横向巡逻和响应事件 |

`navigation-2d-v1` 证明可选择二维导航能力，不证明平面拖放、自由停靠或多方向角色已经完成。[制作工作台](art-workflow/space-v1/README.md)中“松手停在最后合法位置”的规则只属于该入口，上述基线默认产品仍有下落行为；后续平面切片已改变其拖放语义。前期指定地图的用户验收保持原范围，不能扩成默认产品的空间验收。

## 建议优先交付的默认产品切片

以下是完整 D1 的目标清单；首个平面切片的现行语义见[生活装配契约](living-integration-contract.md)，交付与验收见[开发状态](../aliveness-development.md)。表中基线问题不代表后续切片仍全部未实现。先修复空间和身体基础，再检验生活／工作、人格与记忆的可感知作用；第 6／7 期继续保留为后续候选。

后续整合路线见[跨平台桌面互动方案](desktop-environment-plan.md)：本页的基础缺口纳入 D1，原生能力探针、共享桌面几何与窗口互动分别设门槛。新增窗口附着不改变普通平面放置的目标，也不以 macOS 单机结果代替三平台验收。

1. **统一平面位置。** 用地面位置表示走近／走远，把跳跃或被提起的离地高度单独表达。明确可活动区域、完整身体边界、禁区和避让规则；平面模式松手停在合法位置，上方位置可成为稳定停靠点。当前横向百分比配置与旧拖放的迁移／回退须在实施前定清。
2. **补齐最小方向表现。** 在保持角色风格的前提下，制作正面、背面和左右斜向的站立、行走与转身；分别表达移动方向、身体朝向与注视目标。面向用户需要实际身体素材或模型支持，左右镜像与转眼不算完成。先验证最小资源组的运行效果，再决定扩充方向和动作数量。
3. **形成跨区域生活路线。** 从用户设置的停靠位置出发，去有明确用途的另一片区域，观察／停留后返回。目标须真实可达，移动与遮挡连续，不用随机空地点、常驻家具或频繁搬贝壳制造活动量。探索不能以遮挡工作为代价。
4. **将环境因果接回路线。** 复用现有鼠标位置、粗粒度键盘、可信工作元数据和生命周期；在当前位置让路／留意、守候、恢复原目标并返回。新增窗口几何或内容感知另定范围，不能在此假定已有。

保留现有导航、连续接触与物件拥有权、唯一身体协调器、共享完成语义和可信存档。新表现必须进入默认主页面，制作工作台只用于制作和回归。接口、角色兼容、坐标迁移和素材绑定由实际实施范围落成契约，本页不预设新 API 已存在。

## 可见验收条件

| 操作／场景 | 待实现后必须看到的结果 |
|---|---|
| 拖到中上部合法位置后松手 | 人物留在该处，命中区、气泡与阴影一致，无下坠回底边；靠边或禁区按明确规则安全放置 |
| 在不同纵向位置间移动 | 人物沿实际二维路线行走，方向、转身和前后遮挡连续，能够停稳 |
| 停留并关注用户 | 人物能以真实正面／斜正面身体表现面向用户；视线不代替身体朝向 |
| 探索时鼠标接近、持续输入或出现工作关注 | 从实际位置安全交接，保留目标；许可恢复后续接，不重播已完成拿放 |
| 完整跨区域循环 | 从用户停靠点出发，观察、返回并停留，重复执行仍有完整因果链 |
| 与 main 同场景对照 | 用相同尺寸和输入录制默认产品，直接呈现上述空间与朝向差异，交由用户判断变化和 LIVE 感 |

自动化验证合法位置、路线、身份、完成与恢复；真实运行画面验证姿态和连续性；用户另行验收生动程度。原生隔离 profile、物理键鼠、多屏、真实 Host、跨平台与资源结果各自结算。上述条件按实际实现与新验证逐项结算；本页的问题复核本身不构成通过证明。
